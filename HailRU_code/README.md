# HailRU research code

Code accompanying the surface hailfall forecasting study. The eight original notebook filenames are retained, with code-only cells and cleared outputs.

## Experiments

| Notebook | Corresponding experiment |
| --- | --- |
| `dataset_making.ipynb` | Prepares the input sequences, Gaussian-diffused hailfall labels, and station-based masks used in the forecasting experiments. Saves compressed samples and their file indexes for an existing dataset split. |
| `HailRU.ipynb` | Trains the supplied HailRU configuration for the main forecasting experiment. Uses the station-based mask and weighted loss, and saves validation-selected checkpoints. |
| `DIFF_Trans.ipynb` | Trains the differential-transformer baseline used in the model comparison experiment. Preserves the supplied transformer architecture and unmasked forward pass. |
| `3DUnet.ipynb` | Trains the U-Net baseline associated with the manuscript's U-Net comparison. The supplied implementation uses two-dimensional convolutions; the original filename is retained for traceability. |
| `Results.ipynb` | Computes station-based overall forecast scores for the quantitative evaluation experiment. Reports contingency counts, accuracy, precision, recall, TS, and ETS, and saves a CSV table. |
| `Region_results.ipynb` | Evaluates the geographical distribution of cases and forecast skill in the regional analysis experiment. Produces radar-domain and regional scores, distribution maps, and regional comparison figures. |
| `case_study.ipynb` | Compares observations and model forecasts for an individual hailfall event. Plots radar reflectivity, station observations, forecast fields, and hit, miss, and false-alarm counts. |
| `Statistical_Analysis.ipynb` | Supports the pre-hail predictor analysis using matched hail and convective no-hail samples. Contains extraction and statistical functions, and plots the predictor figure from saved statistics and paired-effect tables. |

`project_config.py` centralizes paths, split names, checkpoint locations, and runtime settings. It also loads portable sample indexes and remaps paths embedded in existing catalogs.

## Setup and execution

Use Python 3.10 or later and install the dependencies from the repository root:

```bash
python -m pip install -r requirements.txt
python -m pip install -r requirements-maps.txt
jupyter lab
```

The map dependencies are required for `Region_results.ipynb`; GeoPandas is also needed when the case study uses a shapefile. Install a PyTorch build compatible with the available hardware; training uses one GPU when available and otherwise falls back to CPU.

Edit `project_config.py`, restart the notebook kernel, and run the selected notebook from top to bottom. Run data preparation separately for each existing split, then training, evaluation, and case analysis as needed; predictor plotting uses its saved statistics independently. Dependency files list required packages; the original frozen environment was not supplied.

## Required inputs

The source archive contains code only. Supply the following external inputs, or point the configuration to existing locations:

| Location | Required content |
| --- | --- |
| `data/catalogs/<split>/` | `data_dic_nwp.pkl` and `mask_dic_all.pkl`; evaluation additionally uses `train_dic_matrix.pkl`. |
| `data/samples/<split>/` | Prepared `.npz` samples, generated by `dataset_making.ipynb` or referenced by existing indexes. |
| `data/docs/` | `RADAR_Format_DOC/` and `NWP_Format_DOC/` geographic extent files. |
| `weights/` | Compatible Lightning checkpoints selected through `project_config.py`. |
| `data/boundaries/` | WGS84 city boundaries for the case study. |
| `outputs/statistics/` | `tidy_stats.csv` and `paired_robust_effect_table_max_max.csv`; equivalent Parquet files are also supported with `pyarrow`. |

Raw catalogs map each case ID to ordered radar/NWP file lists and a `label` list of hailfall `(x, y)` coordinates per radar frame. Station dictionaries map case IDs to station coordinates; sample indexes map case IDs and sample keys to `input`, `mask`, and `output` paths. Each `.npz` uses `arr_0`: inputs have shape `(102, 401, 401)`, masks `(401, 401)`, and targets `(20, 401, 401)` in the supplied generator. Paths may be absolute or relative to the repository root; use `PATH_REMAP` for relocated datasets.

Training reads the supplied `train` and `validation` indexes without creating a new random split. Raw-catalog creation and the manuscript's temporal-block partitioning are prerequisites outside this archive. Outputs are written under `outputs/` and checkpoints under `weights/`.

## Source consistency and validation

- The HailRU trainer uses an unweighted input layer and LeakyReLU output; overall evaluation uses sigmoid output, while regional and case analysis use channel-weighted sigmoid variants. These supplied differences remain explicit and require matching checkpoints and verification against the final manuscript.
- The generator includes 80 radar channels, 12 channels from three successive NWP fields, and 10 historical hailfall channels. Verify the availability of those NWP fields at forecast issuance and the final manuscript's input specification.
- The case-study DIFF-T branch now instantiates the transformer from `DIFF_Trans.ipynb` and requires its own checkpoint. Its U-Net legend reads `U-Net` to match the supplied 2D implementation; an observation-frame override was removed, and time labels follow the selected source frames.
- The paired-effect generator `compute_paired_robust_effects.py` was absent from the upload. Supply its saved effect table for the final statistical figure; the included signed-AUC functions compute a different statistic.
- Notebook syntax, input-path helpers, synthetic data preparation, and synthetic plotting are checked. Full training and reproduction of manuscript results require the research data, compatible checkpoints, and a configured PyTorch environment.
